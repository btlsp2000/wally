CORE INPUT PROTOCOL

The v1.0.17 engine utilizes an aggressive space-delimited tokenizer designed for high-speed HTML5 canvas rendering. All vector data enters the engine through the "PASTE SDJ STRING" panel located in the Data Protocol sidebar.

The RegEx Gatekeeper

To protect the parser from failing on invisible formatting characters, the input panel routes all pasted data through a native JavaScript Regular Expression sanitization function.

.replace(/[\r\n\t]+/g, ' ') .replace(/\s{2,}/g, ' ') .trim()

This gatekeeper instantly strips carriage returns, line breaks, and tabs, flattening multi-line text into the pure 1-dimensional string required by the tokenizer. This allows users to paste raw columns directly from Excel or Google Sheets without breaking the canvas rendering loop.

Entity Tagging Requirement

The tokenizer sweeps left-to-right looking for valid floats. Naked coordinates will be dropped unless they are prefaced by a valid WallyCAD entity tag (e.g., [WALL], [LINE], [CIRCLE]) which tells the engine which active array to push the subsequent vector nodes into.

THE DATA FUNNEL

External data steps down through three distinct tiers of formatting complexity before hitting the canvas.

Tier 1: Heavyweight JSON

Standard JavaScript Object Arrays (e.g., [{"type":"line","x1":0...}]). Universal for web APIs, but bloated with syntax. Cannot be pasted directly into the core engine. Must be routed through the /jsontowally Data Converter or standalone Flattener module first.

Tier 2: Multi-Line SDJ

Human-readable Space-Delimited JSON blocks. Contains no JSON keys or brackets, but retains line breaks for notebook readability.

[LINE] 10 90 90 90 T:0 [LINE] 10 95 90 95 T:0

Supported Natively. The RegEx Gatekeeper intercepts these line breaks upon paste and sanitizes them into Tier 3 automatically.

Tier 3: The 1D Continuous String

The absolute bottom of the funnel and the engine's native language. A single uninterrupted text stream separated only by single spaces.

[LINE] 10 90 90 90 T:0 [LINE] 10 95 90 95 T:0

This format achieves zero-latency parsing, allowing the core to instantly render thousands of vectors without halting the browser thread.

.WALLY DATA SYSTEM

The native .WALLY file format and its flattened Space-Delimited JSON (SDJ) counterpart utilize a highly condensed, polymorphic data architecture. This design keeps file sizes small and parsing speeds near-instantaneous.

Width Parameter Sensitivity

The core rendering loop is intensely sensitive to the "Width" parameter (stored natively as thick in JSON objects, or as the T: tag in SDJ strings).

Rather than bloating the file format with redundant, entity-specific variables (like radius, scale, or offset), the WallyCAD engine hijacks this single numeric value. The engine dynamically changes its mathematical behavior and routes the data through different algorithms entirely based on the leading Entity Tag.

[ENTITY] X Y X Y ... T:[WIDTH SENSITIVITY]

ENTITY ROUTING LOGIC

When the core engine parses the T: parameter, it applies the following contextual translations during the canvas rendering phase:

[WALL] : Vector Intersection

[WALL] 0 0 120 0 T:6
Triggers the heavy Vector Intersection Algorithm (VIA). The engine splits the coordinate baseline, pushing parallel geometry outward by exactly half the width (3 units) to create physical mass.

[TEXT] : Scale Multiplier

[TEXT] 10 10 T:1.5
Bypasses physical thickness. The parameter acts as a Font Scale Multiplier, increasing the base font size by 1.5x.

[CIRCLE] : Radial Distance

[CIRCLE] 60 48 T:12
The width parameter dictates the exact Radius of the sweep.

[DIM] : Extension Offset

[DIM] 0 96 120 96 T:15
The parameter sets the perpendicular offset distance for the dimension line away from the measured nodes.

[LINE] : 1D Bypass

[LINE] 10 10 90 90 T:0
Defaults to 0. Bypasses all complex math to render as a pure 1D stroke, ignoring physical thickness entirely.

PARABOLA HYBRID V2

The wallycad.com/parabola V2 standalone merges the original y = x² mathematical macro framework with a responsive visualizer and optimized data extraction pipeline.

Core Parameters

The tool strictly adheres to the original CLI input syntax parameters:

  • Vertex (vx, vy): The origin anchor point mapping the geometric center.
  • Domain (Xmin, Xmax): The absolute limits dictating the horizontal span of the curve.
  • Grid Scale: The spatial multiplier expanding the base y = x² function.

Dual-Mode Geometry

Users can instantly toggle between two distinct subdivision algorithms:

  • Uniform Mode: Slices the domain into a user-defined number of equal, straight-line segments.
  • Fractional Notebook Mode: Uses a hardcoded geometric progression (0, ±1/4, ±1/2, ±1, ±3/2, ±2) designed to land precisely on standard imperial grid intersections.

PIPELINE & VISUALIZER

Pre-Flattened SDJ Output

The output generator eliminates external dependencies (like the Flattener or JSON converter). Calculated nodes are packaged directly into a 1-dimensional, space-delimited string of [LINE] entities.

[LINE] 0 0 4 1 [LINE] 4 1 8 4 [LINE] 8 4 16 16 T:0

This strict formatting guarantees zero-latency execution when pasted into the core v1.0.17 engine's CLI prompt.

Responsive Auto-Scaling

The internal HTML5 canvas calculates the coordinate deltas and dynamically scales the view. The parabola remains perfectly centered and visible on-screen regardless of the extreme aspect ratios caused by high Grid Scale multipliers.

Floating-Point Accuracy

To prevent cumulative drift, all vertices and endpoints are rounded precisely to 4 decimal places before SDJ array injection, safeguarding the structural integrity of intersecting CAD entities.

PMAPPER MODULE

The Perimeter Hub (/pmapper) is a specialized standalone module designed to translate geographical coordinates (Latitude/Longitude) into planar Cartesian geometry for WallyCAD preview and export.

Canvas Translation Engine

The core rendering function applies a direct mathematical translation to plot spherical coordinates onto a 2D HTML5 canvas, shifting the origin to keep the US West Coast in frame:

let y = canvas.height - ((Lat - 31) * 40); let x = (Long + 125) * 40;

This isolates geographical polygons—such as the borders of Washington, Oregon, or California—and scales them for immediate visual verification before they are committed to an SDJ string.

Dynamic State Library

The left pane sidebar dynamically builds a clickable library based on an internal JSON object (Perimeters). Clicking any card instantly recalculates the bounds and renders the closed loop on the preview canvas.

QC COMMAND LINE

The /pmapper module features an integrated QuickClick (QC) command line interface anchored to the bottom of the viewport, enabling rapid data entry and execution without touching a mouse.

The ADD Syntax

Users can inject new geographical boundaries directly into the active session memory by typing into the QC CLI. The command follows a strict tokenized syntax:

ADD [NAME] [LAT1] [LON1] [LAT2] [LON2]...

Example: ADD NEVADA 42.0 -114.0 42.0 -120.0...

Pressing Enter will parse the string, push the new entity into the Perimeters library, rebuild the sidebar, and instantly render the new state.

Global QC Hotkeys

When the CLI input box is not focused, the module listens for global keystrokes to execute macro commands:

  • [ 4 ] : Instantly renders the Four Corners geometry.
  • [ C ] : Clears the canvas and deselects the active state.
  • [ G ] : Pipes the active state's raw coordinate data out for G-Coder formatting.
