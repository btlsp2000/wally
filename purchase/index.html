Data Processor

Field Data Entry & Parsing Rules

The translation layer between raw field shorthand (including QuickClick strings) and actionable coordinate geometry. The processor normalizes bearings, distances, and node identifiers before passing them to the Traverse Engine.

Standard Input Syntax:

[NODE_ID],[BEARING_QUADRANT],[DEGREES],[MINUTES],[DISTANCE] Ex: N1,NE,45,30,125.5
IndexField ElementParser Logic / Constraint
0Node IDString. Must be unique per loop.
1QuadrantEnum: NE(1), SE(2), SW(3), NW(4)
2DegreesInteger: 0 to 89
3MinutesFloat: 0.0 to 59.99
4DistanceFloat: Decimal feet (e.g., 12.50)
Parsing Hook: (split-string input-str ",")

Traverse Engine

Core Coordinate Geometry & Vector Translation

The primary vector generation loop. The Traverse Engine consumes parsed field data from the Data Processor, applying standard trigonometric transformations to plot sequential Cartesian nodes from a Point of Beginning (POB).

ΔX (Easting) = Distance × Sin(Azimuth)
ΔY (Northing) = Distance × Cos(Azimuth)
Traverse StateGeometric Logic & Validation
Open LinkSequential node generation without geometric termination.
Closed LoopFinal vector must return to POB. Engine calculates Error of Closure.
Side-ShotSpur vector generated from occupied node. Does not advance traverse.

Engine Core: Polar Coordinate Resolution

; AutoLISP Vector Translation Routine (defun c:CALC_NODE (pt1 quad deg min dist / az ang pt2) ; Convert parsed Bearing to absolute Azimuth (setq az (brg->az quad deg min)) ; Translate Azimuth to AutoLISP Radian Standard (setq ang (az->rad az)) ; Plot Cartesian Node via internal polar projection (setq pt2 (polar pt1 ang dist)) (return pt2) )

Plane to Plane (PTP)

3DFace Intersection Logic

Legacy logic established circa 1992. Computes the intersecting line segments between 3D faces using similar triangle proportionality.

Formula: d = (a * b) / c

The routine calculates intersection parameters by resolving proportional vector lengths between opposing plane coordinates.

; AutoLISP PTP Intersection Extractor (defun c:PTP ( / p1 p2 p3 p4 distA distB distC finalD) (setq p1 (getpoint "\nSelect Plane 1 Node A: ")) (setq p2 (getpoint "\nSelect Plane 1 Node B: ")) ; Apply similar triangle intersection logic (setq distA (distance p1 p2)) (setq distB 1.0) ; Proportional factor b (setq distC 2.0) ; Proportional factor c ; d = ab/c (setq finalD (/ (* distA distB) distC)) (princ (strcat "\nIntersection Segment Length: " (rtos finalD 2 4))) (princ) )

/shots Module (CofP)

The Calculus of Pool: Vector Analysis

Standalone shot diagrammer utilizing a center-anchored (0,0) coordinate system. The engine calculates multi-factor shot analysis by applying geometric ghost-ball alignment and tangent-line collision logic.

VariableDefinitionEngine State
C(x,y)Cue Ball OriginQC or Drag Input
O(x,y)Object Ball Pos.QC or Drag Input
P(x,y)Pocket / TargetRadius Collision Zone
G(x,y)Ghost Ball NodeEngine Calculated
Vector G = Vector O - (2r) * normalize(P - O)
