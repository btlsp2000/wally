CORE INPUT PROTOCOL

The v1.0.17 engine utilizes an aggressive space-delimited tokenizer designed for high-speed HTML5 canvas rendering. All vector data enters the engine through the "PASTE SDJ STRING" panel located in the Data Protocol sidebar.

The RegEx Gatekeeper

To protect the parser from failing on invisible formatting characters, the input panel routes all pasted data through a native JavaScript Regular Expression sanitization function.

.replace(/[\r\n\t]+/g, ' ') .replace(/\s{2,}/g, ' ') .trim()

This gatekeeper instantly strips carriage returns, line breaks, and tabs, flattening multi-line text into the pure 1-dimensional string required by the tokenizer. This allows users to paste raw columns directly from Excel or Google Sheets without breaking the canvas rendering loop.

Entity Tagging Requirement

The tokenizer sweeps left-to-right looking for valid floats. Naked coordinates will be dropped unless they are prefaced by a valid WallyCAD entity tag (e.g., [WALL], [LINE], [CIRCLE]) which tells the engine which active array to push the subsequent vector nodes into.

THE DATA FUNNEL

External data steps down through three distinct tiers of formatting complexity before hitting the canvas.

Tier 1: Heavyweight JSON

Standard JavaScript Object Arrays (e.g., [{"type":"line","x1":0...}]). Universal for web APIs, but bloated with syntax. Cannot be pasted directly into the core engine. Must be routed through the /jsontowally Data Converter or standalone Flattener module first.

Tier 2: Multi-Line SDJ

Human-readable Space-Delimited JSON blocks. Contains no JSON keys or brackets, but retains line breaks for notebook readability.

[LINE] 10 90 90 90 T:0 [LINE] 10 95 90 95 T:0

Supported Natively. The RegEx Gatekeeper intercepts these line breaks upon paste and sanitizes them into Tier 3 automatically.

Tier 3: The 1D Continuous String

The absolute bottom of the funnel and the engine's native language. A single uninterrupted text stream separated only by single spaces.

[LINE] 10 90 90 90 T:0 [LINE] 10 95 90 95 T:0

This format achieves zero-latency parsing, allowing the core to instantly render thousands of vectors without halting the browser thread.

THE 3 DIM MODES

The engine supports three dimension types to accurately document architectural layouts.

1. [DIM] - Aligned

The standard dimension. The measurement string runs parallel to the angle between Point 1 and Point 2. Used for diagonals and angled walls.

2. [DIMH] - Horizontal

Locks measurement strictly to the X-Axis. Even if P1 and P2 are at different heights, the engine calculates only the horizontal distance.

3. [DIMV] - Vertical

Locks measurement strictly to the Y-Axis. Text is automatically rotated 90 degrees to read bottom-to-top.

Smart Auto-Dimensioning

Select any object before typing DIM, DIMH, or DIMV. The engine bypasses manual coordinates, reads extents, and wraps a scaled dimension string automatically.

SDJ Dimensioning

SDJ SYNTAX

The core schema for dimensioning relies on the T: parameter to define the offset distance.

[TYPE] X1 Y1 X2 Y2 T:OFFSET "TEXT"

The T: Offset Parameter

Unlike Walls or Lines where T: controls thickness, in a DIM entity T: dictates how far to pull the dimension line away from the baseline nodes.

  • T:15 throws the line 15 units outward.
  • T:-20 throws the line 20 units in the opposite direction.

Command Line Examples

[DIMV] 0 0 0 108 T:-20

Measures the vertical height of a 108-unit wall, placing the dimension string 20 units to the left.

[DIMH] 0 0 192 0 T:15 "16'-0\""

Measures a 192-unit span, offsets it 15 units, and overrides numeric display with custom architectural text.

DATA CONVERSION

INTERNAL VS. STANDALONE

A core architectural decision in the WallyCAD ecosystem dictates where the heavy lifting of data sanitization and vector processing takes place.

Inside Core Engine

When raw, unformatted text or multi-line macros are pasted directly into the v1.0.17 Studio dashboard, the core engine's internal RegEx Gatekeeper must fire:

  • Scrubbing tabs and carriage returns.
  • Executing Vector Intersection Algorithms (VIA) for wall mitering in real-time.
  • Parsing raw notebook fractions into floating-point decimals.

Standalone Modules

Generators like /parabola, /shutters, and /array-polar act as external preprocessing servers. By the time data leaves a standalone module, it is already calculated, rounded to 4 decimals, and flattened.

The Advantage: Bypassing core engine parsing yields absolute zero-latency rendering when the resulting 1D string hits the canvas.

Spread 06 // Preprocessing Q2 // Modules

DATA TYPES

JSON VS. .WALLY

WallyCAD supports multiple schemas, though the native format remains vastly superior for computational rendering speed.

1. JSON (Object Notation)

[ {"type": "line", "x1": 0, "y1": 0, "x2": 10, "y2": 10, "thick": 0} ]
  • Universal standard for web APIs and database storage.
  • Highly legible for traditional software development.
  • Drawback: Contains massive syntactical overhead. Quotes, commas, and repetitive keys bloat file sizes and tax the rendering loop.

2. .WALLY (Space-Delimited JSON)

[LINE] 0 0 10 10 T:0
  • A condensed, polymorphic string structure.
  • Parses contextually based entirely on parameter sequence.
  • Advantage: Eliminates all redundant variables, providing the ultra-lightweight 1D stream required for WallyCAD's high-speed tokenizer.

WallyCAD S2-82 Module v1.0.17

VECTOR MIRROR (/MIR)

System documentation for the S2-82 Vector Mirror engine. This standalone module mathematically reflects geometry coordinate blobs across a defined directional axis vector (V3) to rapidly generate symmetrical structural elements.

1. Axis Definition (V3)

The module establishes the plane of reflection by interpreting user input as a directional vector originating from (0,0):

  • Horizontal Mirror: V3 = (1, 0). Reflects geometry across the X-axis plane.
  • Vertical Mirror: V3 = (0, 1). Reflects geometry across the Y-axis plane.
  • Arbitrary Pitch: Custom coordinates (e.g. 1, 1) mirror across diagonal planes like a 45° gable roof or rafter line.

2. Coordinate Parsing

The input processor ingests raw WallyCAD blobs via regex (split(/\s+/)) and iterates through the flat array in pairs, mapping every two sequential floats to a target Point (P).

Spread 07 // S2-82 Engine Q2 // /mir
Vector Calculus

REFLECTION MATH

The engine bypasses heavy transformation matrices by utilizing pure vector projection to achieve zero-latency geometric reflection.

Unit Vector Normalization

V3 is normalized into a Unit Vector (U) with magnitude 1. A fail-safe defaults to the X-axis if a zero-magnitude vector is entered.

const mag = Math.sqrt(vx * vx + vy * vy); if (mag === 0) { vx = 1; vy = 0; } const ux = vx / mag; const uy = vy / mag;

The Reflection Equation: P' = 2(P · U)U - P

For each parsed point (px, py), the engine calculates the dot product against the unit vector, producing mirrored coordinates rounded to 4 decimals.

// Dot Product (P · U) const dot = px * ux + py * uy; // Reflection Vector calculation let mx = (2 * dot * ux - px).toFixed(4); let my = (2 * dot * uy - py).toFixed(4); result.push(`${mx} ${my}`);

FOOTPRINT OFFSET (/OFFSET2)

The Footprint Offset Generator is a specialized architectural module. It calculates the outward-expanded baseline required to render a physical [WALL] entity around an exact interior room loop without shrinking the square footage.

1. Winding Detection

Calculates polygon area to determine if coordinates are Clockwise or Counter-Clockwise. This guarantees the offset always pushes outward, eliminating manual coordinate guesswork.

2. Baseline Halving

WallyCAD walls render equally on both sides of a coordinate baseline. The module automatically divides wall thickness by two to calculate the mathematically perfect center node matrix.

3. Path Closure Validation

If fed an open path, the data parser intercepts it and appends the first coordinate to the end of the array, forcing a closed geometric loop suitable for architectural structures.

PMAPPER MODULE

The Perimeter Hub (/pmapper) is a specialized standalone module designed to translate geographical coordinates (Latitude/Longitude) into planar Cartesian geometry for WallyCAD preview and export.

Canvas Translation Engine

The core rendering function applies a direct mathematical translation to plot spherical coordinates onto a 2D HTML5 canvas, shifting the origin to keep the US West Coast in frame:

let y = canvas.height - ((Lat - 31) * 40); let x = (Long + 125) * 40;

This isolates geographical polygons—such as the borders of Washington, Oregon, or California—and scales them for immediate visual verification before they are committed to an SDJ string.

Dynamic State Library

The left pane sidebar dynamically builds a clickable library based on an internal JSON object (Perimeters). Clicking any card instantly recalculates bounds and renders the closed loop on the preview canvas.

/TRUSS ANALYTICS

v1.0.10 | "The Year of the Trailer"

This module transitions WallyCAD from architectural elevation into dynamic structural engineering. The Truss Analytics standalone engine focuses on PTP (Point-To-Point) Logic, mathematically distributing load-bearing nodes across a specified span.

The QC Command Syntax

Replacing traditional graphical UI inputs, the engine utilizes a high-speed command line syntax to instantly generate geometry:

QC > T[SPAN]-[DEPTH]-[PANELS]

Example: T7-1-6 renders a truss with a 7-foot span, 1-foot depth, divided into 6 equal panels.

Geometric Distribution

  • Panel Width: Calculated automatically as Span / Panels.
  • Top Chord (T-Nodes): Placed incrementally at every panel width interval at the specified Depth (Y-axis).
  • Bottom Chord (B-Nodes): Offset horizontally by exactly half a panel width (i + 0.5) and pinned to Y: 0.000 to create zigzag triangulation geometry.

JSON Export Protocol

To bridge the gap between WallyCAD and external engineering tools, the module bypasses standard SDJ strings in favor of a structured data export.

DUAL OUTPUT ENGINES

Engine 1: DXF Machine Path

The primary compiler translates the matrix into a universal Release 12 (R12) DXF plain-text schema, stripping away visual context in favor of pure CNC and CAD readability.

  • Primitive Decomposition: To ensure cross-compatibility with older machine protocols, parametric Wally Box entities are automatically decomposed into four discrete, endpoint-connected LINE vectors during compilation.

Engine 2: PDF Plotter

The secondary engine leverages the jsPDF library to generate flat, 8.5" x 11" architectural plots for human review. It applies a standard drafting pen weight (0.01) and establishes strict 0.5" document margins.

  • Cartesian Y-Axis Inversion: PDF coordinates originate from top-left (0,0), while WallyCAD mathematics originate from bottom-left. The engine intercepts all Y-coordinates and executes real-time inversion:
    y = pageHeight - marginY - coordinate.
