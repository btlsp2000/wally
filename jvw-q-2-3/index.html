DATA CONVERSION

INTERNAL VS. STANDALONE

A core architectural decision in the WallyCAD ecosystem dictates where the heavy lifting of data sanitization and vector processing takes place.

Inside (Internal to) Core Engine

When raw, unformatted text or multi-line macros are pasted directly into the v1.0.17 Studio dashboard, the core engine's internal RegEx Gatekeeper must fire.

  • Scrubbing tabs and carriage returns.
  • Executing the Vector Intersection Algorithm (VIA) for wall thickness calculations in real-time.
  • Parsing raw notebook fractions into usable floating-point decimals.

Standalone Modules

Generators like /parabola, /shutters, and /array-polar act as external preprocessing servers. By the time data leaves a standalone module, it has already been calculated, rounded to 4 decimal places, and flattened.

The Advantage: Bypassing the core engine's internal conversion routines yields absolute zero-latency rendering when the resulting 1D string hits the main canvas.

DATA TYPES

JSON VS. .WALLY

WallyCAD supports multiple data schemas depending on the specific workflow requirement, though the native format remains vastly superior for computational speed.

1. JSON (JavaScript Object Notation)

[ {"type": "line", "x1": 0, "y1": 0, "x2": 10, "y2": 10, "thick": 0} ]
  • The universal standard for web APIs and database storage.
  • Highly legible for traditional software development.
  • Drawback: Contains massive syntactical overhead. Brackets, quotes, and repetitive keys bloat file sizes and slow down the rendering loop.

2. .WALLY (Space-Delimited JSON)

[LINE] 0 0 10 10 T:0
  • A condensed, polymorphic string structure.
  • Parses elements contextually based entirely on parameter sequence.
  • Advantage: Eliminates all redundant variables, providing the ultra-lightweight, continuous 1D stream required for WallyCAD's high-speed tokenizer.
